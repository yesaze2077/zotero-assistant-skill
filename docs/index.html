01

先让助手知道怎样工作

安装 Zotero 助手 Skill

先打开已经安装并登录的本地 Codex 或 Claude Code。把下面的话发给它，安装、文件检查和必要命令由助手处理。

你需要准备

一个可工作的本地 AI 客户端

它需要能在你的电脑上读取文件、安装 Skill，并在获准的范围内执行本地操作。首次登录由你本人完成。

浏览器里的普通 AI 聊天不自动拥有本机文件与 MCP 权限；Claude Code 与 Claude Desktop 也要分别核实。

你将安装什么

一套工作方法与辅助脚本

安装名是 zotero，入口是仓库根目录的 SKILL.md。它会指导助手工作，不自带 Zotero、MCP Server、OCR 软件或其他可选 Skill。

是否需要补装组件，由下一步的真实检查决定。

复制到本地 Codex / Claude Code

请从 https://github.com/yesaze2077/zotero-assistant-skill 为当前客户端安装 Zotero 助手 Skill，安装名为 zotero，入口在仓库根目录 SKILL.md。先检查来源、文件内容与当前客户端支持的安装方式，再完成安全的本地安装。保留已有同名 Skill 的内容和配置；如果发生冲突，先给出具体处理方案。不要把安装 Skill 当成 Zotero、MCP 或 OCR 已安装。安装后确认当前客户端能发现并使用它，不要让我手动执行终端命令。

安装完成看什么？ 助手应确认已找到 zotero 并读取其入口。若客户端需要刷新或重新打开对话，只做这一步，然后再次验证。接着说：“使用 Zotero 助手，带我从当前进度开始。”

项目入口：yesaze2077 / zotero-assistant-skill ↗

02

每一层都要实际读一次

连接你的文献库

已有软件直接复用，缺什么再补什么。先让助手判断当前能力；缺少 Homebrew、uv 或某个可选组件，不应直接中止任务。

1

Zotero Desktop：保存与打开文献

助手检查应用是否安装、是否正在运行。缺失时从 Zotero 官方入口安装，再实际打开主窗口。本地体验可以先不登录 Zotero 账号；需要同步时再配置。

应用能正常启动，不只是安装文件已经下载。

官方下载 ↗ · 安装说明 ↗

2

Connector：从浏览器保存论文

只安装你实际使用的浏览器扩展。Chrome、Edge、Firefox 从官方下载页进入对应入口；Safari 用户启动 Zotero 后，在 Safari 的“设置 → 扩展”中检查 Zotero Connector。

打开论文介绍页，用 Connector 保存到指定集合，再让助手读回同一条目的作者、年份和 DOI。优先保存论文介绍页，元数据通常更完整。

当前浏览器已启用，并且真实保存的条目能在库里找到。

官方添加条目说明 ↗ · Safari 说明 ↗

3

Local API：让本机程序读到库

保持 Zotero 运行。助手实际检查本地 API 的条目与集合读取。如果未开放，检查 Zotero 设置 → 高级中允许本机其他应用通信的选项，以当前版本的界面文字为准。助手能代操作就完成，确实需要你点击时只指出必要一项。

Local API 本身不需要云端 API Key。 不要为了本机读库把密钥贴进聊天，也不要修改 Zotero 数据库。

条目与集合请求返回有效结果；空库返回空列表也可以正常。
4

MCP：让当前 AI 客户端调用读取工具

MCP 是 AI 客户端与 Zotero 之间的工具连接。助手复用已有服务；确需安装时核实来源、维护状态、系统兼容性与读取范围，只选择一个实现。先备份配置，只改 Zotero 对应设置，保留已有服务。

安装 Skill 不会自动完成 MCP 配置。Codex 中连接成功，也不代表 Claude Code 已经连接；换客户端要重新验证。

MCP 协议连接成功，并在你正在使用的客户端中实际调用集合读取工具。
一次交给助手处理

使用 Zotero 助手，检查这台电脑上的 Zotero Desktop、我正在使用的浏览器 Connector、Local API 和当前 AI 客户端的 MCP。复用已可用组件，完成缺失的必要安装与配置，保留已有设置。依次实际读取顶层集合、最近 5 篇文献的标题/作者/年份，并检查一篇真实 PDF 的访问和全文覆盖。先说明能力是否可用；确实需要本人点击时，一次只给一个必要动作。没有全文就明确说明，不要用摘要代替。

连接与全文是两次验收。 读到了集合，不代表 PDF 已下载；读到了摘要，也不代表正文已读。已有库可以先从现成文献阅读，暂缓 Connector 保存测试，避免重复导入。
03

从一篇、一段、一个问题开始

亲自读第一篇论文

先选一篇与你的研究有关、正文可读的论文。不追求一次整理整个库，先走通一个能反复使用的小流程。

库里已经有论文

直接复用现有条目

告诉助手集合名称或目标论文，让它核对条目归属与 PDF 附件。无需为了“体验导入”再保存一次。

库还是空的

给一个链接、DOI 或 PDF

助手核实来源，完成已授权的导入并读回。如果没有偏好，可请它寻找合法开放获取的候选；付费墙不会被绕过。

集合：按主题组织→文献条目：标题、作者、年份→PDF 附件：论文正文
1

定位论文，核对来源

助手找到真实条目和附件，打开目标论文。先确认标题、作者、年份、期刊与 DOI；文件名不能替代题录核验。

2

带着一个问题看正文

例如：“作者用什么证据支持这个结论？” 助手检查 PDF 全页文字覆盖，再阅读相关章节。完整研究卡片需要覆盖问题、方法、结果和局限；要求通读时，应读完全部正文并说明范围。

3

留下一条你自己的理解

让助手定位一段短证据及其页码。你可以在 Zotero 中高亮并写一句笔记，也可以在聊天里用自己的话说：“这条证据对我的研究有什么用？”

由你实际完成一次阅读动作。助手写了示范或生成卡片，不等于你已经练习。
开始第一篇体验

使用 Zotero 助手，带我读第一篇论文。请先从我指定的集合中找一篇与研究问题相关、已有可读 PDF 的论文；如果信息还不够，只问一个关键问题。先核对全文可访问范围，再给我一个阅读问题，定位一段带页码的证据，引导我写一句自己的理解，最后整理成研究卡片和一条可追溯引用。已有条目不要重复导入。

没有全文时： 标明 FULL TEXT NOT AVAILABLE，或明确写出仅阅读了哪些页。可以继续做摘要练习，但全文阅读步骤仍待完成。扫描件先去看“PDF 不能复制或文字乱码”。

04

整理理解，也保存证据

把阅读变成一张研究卡片

卡片要帮你回答“作者做了什么、证据在哪里、我可以怎样使用”。每部分注明来源，未知内容留下空缺或“待核实”。

来源标记它表示什么使用时看什么
Full Text实际读取的论文正文章节与页码；关键数字应回看原页面。
Abstract摘要中明确写出的内容不能据此补出未提供的方法细节或局限。
Metadata题录信息，如作者、年份和 DOI与论文首页或可靠出版来源核对。
Inference助手或你的推断、借鉴思路与原作者的结论分开，并说明推断依据。
研究卡片应包含这些内容结构示例 · 不是一篇真实论文的结论
基本信息

Title / Authors / Year / Journal / DOI；文献类型、作者稿或正式版有差异时说明。

问题与动机

Research Question / Research Motivation：研究要解决什么，为什么需要研究。

研究方法

Research Design / Dataset or Sample / Method / Variables：设计、数据或样本、方法和变量；不存在或未披露的项目明确标注。

发现与局限

Key Findings / Limitations：关键结论及证据页码；原文局限与助手指出的潜在问题分开。

可借鉴与待补

Research Opportunities：用于自己论文的哪一部分，还需要找什么证据；建议可标为 Inference。

Evidence Status

逐部分标注来源，列出实际已读范围、关键页码与尚未核实项；如有 OCR 或提取限制也写明。

生成可继续使用的卡片

请基于这篇论文实际可读取的内容生成研究卡片，包含基本信息、研究问题与动机、设计/样本/方法/变量、关键发现、局限、研究机会，以及 Evidence Status。每部分标注 Full Text、Abstract、Metadata 或 Inference，并给出证据页码。把我的想法与原作者结论分开；补充“用于我论文的哪一部分”和“还需要找什么证据”。未读到或无法核实的信息保持未知。卡片先保存到我指定的本地位置；回写 Zotero 另按我授权的范围处理。

页码优先写 PDF 物理页码；论文印刷页码不同，可同时标注。PDF 共多少页，不等于论文正式引用的起止页码。

05

第一次引用，也要可追溯

完成一次可靠引用

先对照论文首页核对题录，再生成引用。学校格式需单独核实；练习样式通过，不代表正式论文格式已验收。

只做阅读与资料整理

普通参考文献示例即可

让助手生成带来源的引用示例，并注明使用的格式。它是静态文本，后续改作者、年份或编号时不会自动更新。

不使用 Word，可以暂缓 Word 验证，继续阅读与卡片整理。

使用 Word 撰写论文

在练习文档里验收动态引用

新建一份练习文档，确认 Word 的 Zotero 标签页可用，然后插入一条引文、生成参考文献表、点击 Refresh 并检查仍可编辑。

不要拿正在撰写的学位论文测试安装，也不要点击 Unlink Citations 解除关联。

Add/Edit Citation
插入或编辑引文→Add/Edit Bibliography
生成参考文献表→Refresh
刷新后仍可编辑
让助手协助验证 Word

请用这篇论文帮我完成一次 Zotero 引用练习。先核对作者、年份、题名、期刊和 DOI。若我使用 Word，在新建练习文档中检查 Zotero 插件，插入引文和参考文献表，刷新后确认仍能编辑；不要改动我的正式论文。若当前工具无法代操作，只引导我完成最少必要点击，并把未验证步骤留待完成。若我不用 Word，提供明确标注为静态文本的引用示例。

06

上手之后，直接说你的问题

把助手用在每天的研究里

不必每次从安装讲起。给出目标集合、研究问题和想要的成果，助手只检查这次任务需要的条件。

找到值得读的一篇

检索与筛选

按主题、关键词或集合查找文献，先看相关性与全文可用性。

找文献

请在我指定的 Zotero 集合中，围绕我的研究问题筛选 3 篇值得优先阅读的文献。列出题名、作者、年份、相关原因和全文可用状态。先说明筛选依据，不要把标题相关当作内容已经核实。

把文件变成可找回的资料

导入与分类

按实际来源区分论文、学位论文、报告与学校规范，先核对清单和重复风险。

整理资料

请检查我指定目录中的参考资料，做一份可审阅的 Zotero 导入与分类清单，包含文献类型、题录来源、建议集合、疑似重复和待核实信息。只处理指定范围；先不要导入、删除或合并。等我确认具体清单后，再执行获准的操作并读回验证。

比较方法，而不只合并摘要

多篇论文对照

把研究设计、样本、变量和发现放在同一张表里，标出证据覆盖差异。

比较文献

请比较我指定的这几篇论文，按研究问题、设计、样本、方法、变量、发现和局限做对照表。每个关键判断注明来源和页码；仅有摘要的文献单独标明，不补造细节。最后指出可比较的部分和仍缺少的证据。

从你的批注继续思考

摘录与写作提纲

先读取能实际获取的批注，再按主题组织；没有批注不假装已经读到。

整理批注

请读取我指定论文中实际可访问的 Zotero 批注，按主题整理成笔记提纲。保留原文出处与页码，把原文摘录、我写的评论和你的推断分开。若当前接口读不到批注，请说明限制，不要根据论文内容伪造我的阅读记录。

07

保留可用部分，只修故障所在层

遇到问题，从这里找

点击与你现象最接近的一项。报错时告诉助手你正在用的客户端、刚才做了什么，以及不含密钥的错误信息。

安装了 Skill，助手仍然读不到 Zotero

Skill、桌面应用、Local API、MCP 服务和当前会话工具是不同层。配置文件里有名字，只能证明配置存在；独立启动测试通过，也不能替代当前对话的工具调用。

分层诊断

请诊断当前客户端为什么读不到 Zotero。依次检查应用运行、Local API 条目与集合、MCP 协议及读取工具、当前会话加载状态，指出失败在哪一层。保留已有成功配置；修复后实际调用一次集合和条目读取，不要仅凭配置文件或终端测试宣布接通。

能看到文献标题，却打不开 PDF

先检查真实附件是否存在、是否只同步了题录、链接文件是否仍在原位置，以及文件能否本地打开。条目没有 PDF，可能是尚未下载或访问权问题；不能直接判定 MCP 故障。

请助手报告“附件不存在 / 文件未到本机 / 文件路径失效 / 文件加密 / 接口读取失败”中的实际情况。只从你有权访问的来源补全文。

PDF 不能复制、是扫描件，或提取文字乱码

先检查全部页，区分无文字层、部分页未检查、乱码和解析失败。默认抽样结果只能说明已检查的范围。OCR 需要本机已有可用工具；这个 Skill 不捆绑或自动预装 OCR。

需要识别时生成全新副本，保留原 PDF 和批注。默认跳过已有文字页；重做文本层或强制栅格化有额外影响，应在明确范围后处理。

完成后核对原件未变、页数一致、文字覆盖，并抽查中文、双栏次序、表格与关键数字。OCR 流程成功不等于文字正确；旁边的文本文件也可能不含原来就有文字的页面。加入 Zotero 是另一步导入。

先检查，再生成副本

请检查这篇 PDF 的全页文字覆盖，判断是扫描件、乱码、加密还是提取限制。若确实需要 OCR，先说明本机缺少什么，再在已具备工具时生成新的本地副本，保留原 PDF 和批注，不上传文件。校验原件未变、页数和文字覆盖，并抽查关键页面与数字。不要自动强制重做所有页面，也不要把识别成功当作内容准确。

浏览器已装 Connector，但论文没有保存进库

检查你当前使用的浏览器是否真正启用了扩展，Zotero 是否运行，保存弹窗选择了哪个库和集合。打开论文介绍页再测试，并在 Zotero 里读回同一条目；不要连续点击造成重复保存。

如果只缺 PDF，先核实网页是否有可访问的全文。商店显示“已安装”不能代替实际保存验收。

Zotero 官方网页保存排障 ↗

Word 没有 Zotero 标签页，或引用刷新失败

先安全保存当前文档。插件缺失时按 Zotero 官方流程检查；常见入口为 Zotero 的“设置 → 引用 → 文字处理软件”，安装 Microsoft Word 插件后重新打开 Word，具体标签以当前版本为准。

让助手在新建练习文档中测试插入引文、参考文献表与刷新。不要重置整个 Word、删除用户模板或把动态引文改成普通文字来掩盖问题。

Zotero 官方 Word 插件排障 ↗

研究卡片很完整，但看不出是否真的读了全文

要求助手列出实际读取的附件、页码范围、问题/方法/结果/局限的来源页，以及关键证据核验情况。元数据、摘要、搜索片段或被截断的文本窗口，不能替代全文。

若证据不足，请它把对应部分改成“未知 / 待核实”，或标记 FULL TEXT NOT AVAILABLE。你自己的阅读练习状态也应单独保留。

08

知道数据在哪里，操作改了什么

本地读库与 AI 阅读的边界

Local API 在本机访问 Zotero。你使用的 AI 服务如何接收、处理与保留内容，需要按客户端、模型服务及账号设置单独判断。

本机连接

Local API 不是云端库授权

它让本机程序与正在运行的 Zotero 通信，本身不需要云端 Key。启用 Zotero 同步、登录共享库、调用联网题录检索是另外的行为，应按需要分别确认。

交给 AI 理解

选中的论文内容可能进入模型上下文

当助手读取正文并交给模型分析时，相关内容可能提交给所用 AI 服务。“本地读库”不等于“论文内容完全不离开电脑”。需要严格本地处理时，先让助手核实整条处理路径。

本手册本身：不读取你的文献库，不联网统计，不加载外部字体或脚本，不保存搜索词或复制记录。搜索只过滤页面正文；复制只处理你点击的提示词。点击外部链接时，才由浏览器打开对应网站。
  • 本地读取与新副本生成按当前授权执行；原 PDF、批注和 Zotero 数据库保留。
  • 导入、标签、集合调整或笔记回写，按你明确授权的范围执行，并读回验证。
  • 删除、合并、移动原文件和外部上传，先确定具体范围；不把一次读取授权扩大到整个文献库。
  • 在线 OCR 使用前，说明上传内容、用途、费用与保留政策，再由你决定。
  • 配置修改先备份，只改目标设置。不要把密钥、登录令牌或含私人信息的日志贴进公共问题区。

Zotero 自身的数据处理与同步规则见官方隐私说明 ↗；AI 服务的规则需要另查相应服务。

09

保留有用的方法，谨慎增加能力

更新发现与经验沉淀

发现新工具、安装新工具、记录解决办法，是三件不同的事。它们不会因为你安装了这个 Skill 就全部自动发生。

使用时检查

到期再发现

真实使用时检查更新是否到期。正常成功检查间隔至少 7 天；用户明确要求立即重查时可例外。发现器查询公开来源，不提交你的文献内容。

后台每周扫描

需要另建自动任务

须由你授权，并在支持自动任务的客户端中另行创建。 Skill 文件本身不会让电脑定时运行。后台仅在近 14 天有真实使用时检查；无可行动变化保持安静。

新增能力

审核后再启用

候选只代表发现。助手先审查来源、许可证、依赖、兼容性、读写和上传行为，展示具体变更与回滚方式；得到确认才收录或升级。

经验记录由每位用户单独授权。 作者或其他人的授权不适用于你。启用后，只保存经过验证、已脱敏的症状、适用条件、解决步骤与限制；不保存论文全文、文献标识、私人路径或凭据，也不自动改变系统记忆与权限。
想启用时，再发出这条授权

我同意 Zotero 助手在本 Skill 的经验记录中保存经过实际验证、已脱敏的排障方法，包括适用条件、验证证据与限制。不要保存论文内容、个人库标识、私人路径、凭据或未脱敏日志；推测的偏好先问我。这个授权不包括安装新工具、升级主流程、向外部上传或创建后台自动任务。

未验证的想法只能标为待验证；旧方法在新版本上失效时，应停用或重新验证。经验越多，不代表无需检查当前环境。

怎样算走完第一次体验？

下面是验收清单，不是你的个人进度。真实状态由助手逐项核验并记录；软件环境通过，不等于第一篇论文已经读完。

五个核心结果

每一项都来自实际行动

  • 定位了真实库内条目与 PDF 附件。
  • 检查全页覆盖，阅读所需章节并核对关键证据。
  • 你完成了一次高亮、摘录或自己的理解表达。
  • 得到有来源标记、页码和未知项的研究卡片。
  • 生成一条题录核验过、可追溯的引用。
按真实进度续接

可以暂缓，不必重来

五项核心都验证后，进入日常模式。Connector 和 Word 可按用途单独暂缓，不妨碍阅读核心体验。

你也可以明确跳过引导直接解决问题；跳过不会记成完成。换电脑、客户端或浏览器时，只重新验证相关环境。

已验证 / 待处理 / 暂缓 / 不适用 / 受阻分别记录，不以“文件已生成”补齐所有状态。

下次接着做

使用 Zotero 助手，读取我已有的上手进度，告诉我哪些已经验证、哪些仍待完成。先处理现在最有价值的一步，不重复安装或导入。如果我已经给出具体文献问题，就直接解决它，只检查必要条件。

留下结论，也留下它的出处。
