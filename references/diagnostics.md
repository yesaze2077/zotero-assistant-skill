# 连接与环境排障

首次安装或从未配置 MCP：先读 [onboarding.md](onboarding.md) 与 [mcp-setup.md](mcp-setup.md)。本页用于已有环境的针对性故障，不替代从零安装。

先运行 `assistant.py doctor`。它读取本机状态与少量 API 记录，只输出状态，不打印密钥或文献内容。MCP 配置解析成功不代表当前对话已经加载工具；doctor 的 `mcp_runtime` 明确为未测试，需要当前 MCP 实际调用或独立协议握手补证。

按失败所在层处理：

1. Zotero 未安装：核实官方来源、macOS 兼容和安装需求后，在当前授权范围内安装。已安装未启动：可以启动应用，随后重试 API。
2. `http://127.0.0.1:23119/api/users/0/items/top?limit=1` 失败：分辨连接拒绝、权限、HTTP 错误与无效响应。不要修改数据库。Zotero 的设置 → 高级 → 允许此计算机上的其他应用程序与 Zotero 通信，是常规 Local API 开关；先用 GUI 检查当前版本的实际文字。能代操作时直接完成，确需人工才给这一个设置路径。不要把 Web API Key 当本地读取的必要条件。
3. API 正常、MCP 失败：核对现有 `mcp_servers.zotero` 命令是否存在、参数、stdio 与日志；备份并最小修改，不替换其他 MCP 配置。用实际集合读取验收。
4. 独立协议测试通过但当前对话无工具：说明“服务可用，当前对话尚未加载”，刷新 MCP 或新开会话后再验证。不把 CLI 成功当作 Codex 工具已接入。
5. 集合可读、PDF 失败：检查子附件、真实本地路径、文件同步和权限，转 PDF 流程。同步中的云端附件不等于本机已有文件。
6. 只有语义检索失败：回退标题、关键词、作者、标签检索。不要为了普通检索下载嵌入模型或重建全库索引。

现有 54yyyu 0.11.0 的 `zotero-cli config` 只展示配置；它不验证网络，也不是健康检查。真实的只读命令是 `get collections`，而不是 `collections list`。`tags` 和 `collections` 下含写命令，不能整组开放。

可以先修复安全、可逆的局部故障；连续两次针对同一根因的尝试没有新证据时，输出失败层、已排除项与最少下一步，不盲目重装。状态中的缺失可选 OCR 不应阻断已有文本 PDF 的阅读。
