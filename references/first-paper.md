# 第一篇论文：从拿到文件到留下可复用证据

目标是用户亲自走通一次小闭环，得到一份能够继续使用的研究卡片。助手准备材料并代做机械操作，不把一整份说明书交给用户。通常先完成一篇较短、有可读正文、与当前研究问题相关的论文；不承诺固定耗时。

## 选文献与起点

- 已有库：从用户指定集合中找 1–3 篇，优先真实 PDF 已在本机、元数据相对完整、正文可读的论文，推荐一篇并说明与研究问题的关联。用户已指定则直接用，不换成泛泛示例。
- 空库：请用户给一个 DOI、论文链接或已有 PDF；无偏好时提供一篇合法开放获取且主题相关的候选。下载前核实来源，未取得全文不绕过付费墙。没有可选论文时先完成环境部分并保留进度。
- 来自浏览器：打开论文落地页，完成一次 Connector 保存，读回 Zotero 父条目、目标集合、DOI/标题、作者、年份以及附件。已有同条目先复用；为测试 Connector 另选一个未收录条目时，需在用户已授权的体验导入范围内。
- 已有条目可跳过重复导入，但 Connector 的“安装并成功保存”仍是单独待验证能力，不能随之记为通过。

## 一次一小步

### 1. 让用户在 Zotero 找到论文

助手先定位真实条目与 PDF，再打开条目/附件或提供可点击本地文件。只让用户确认看到哪篇。记录 paper_selected。解释一次“文献条目装基本信息，PDF 是它下面的附件”，此后不重复。

### 2. 带着一个问题读

先用元数据与摘要介绍论文大意，明确来源。给用户一个与其论文有关的阅读问题，例如“作者用什么证据支持这个结论？”

检查 PDF 全页覆盖，按实际研究问题阅读相关章节并核对关键页。用户要求完整研究卡片时，覆盖问题、方法、结果和局限所在章节；需通读时读完全部正文，不能用标题/摘要或单个窗口替代。扫描件按 [pdf.md](pdf.md) 处理新副本。无全文时明确 `FULL TEXT NOT AVAILABLE`，提供摘要练习并记录 paper_text blocked，不能完成全文体验。

### 3. 一条自己的摘录或理解

选一段短证据，指出物理页码，必要时加印刷页码。引导用户只做一个动作：在 Zotero 高亮这段并写一句自己的理解，或直接在聊天里用自己的话说“这条证据对我的研究有什么用”。用户原有高亮可复用。

能用当前工具安全代操作时协助打开/定位；没有注释写接口时使用 Zotero 阅读器，不直接改 PDF 或数据库。让用户在做完后用一句话反馈，或实际读取到对应的新批注后记录 reader_practice verified。助手写的示范、创建的笔记或单纯打开 PDF 不算用户完成练习。用户想稍后做时记录 deferred，继续交付可做部分，不反复催促。

### 4. 做第一张研究卡片

按 [reading.md](reading.md) 的证据规则生成本地卡片。至少包含基本信息、问题/动机、设计/样本/方法/变量、主要发现、局限、可借鉴点及 Evidence Status；每部分区分 Full Text / Abstract / Metadata / Inference，引用页码。用户自己的想法与原作者结论分开。没有的信息保持未知，注明 OCR 或提取限制。

卡片里加“用于我论文的哪一部分”和“还需要找什么证据”；这两项允许标记 Inference/待用户确认。交付清晰的文件链接，不以“卡片写好了”冒充用户已经阅读或批准。

### 5. 引用一次

先对照 PDF 首页核对作者、年份、题名、期刊和 DOI。元数据有错，指出影响并在用户允许修改的范围内纠正；否则卡片手动注明正确信息，自动导出仍标记待修。

仅需阅读整理：生成带来源的普通参考文献示例，并说明它是静态文本。

使用 Word：在新建的练习文档中，通过 Zotero 插件执行一次 Add/Edit Citation 和 Add/Edit Bibliography；再 Refresh，检查引文与参考文献仍能更新。不要拿正在撰写的学位论文当安装测试文档，不用普通文字冒充 Zotero 动态字段。没有 Word/不使用 Word则将 word_citations 记为 not_applicable/deferred，不阻断文献阅读。

### 6. 结束与续接

交付研究卡片、来源页码和引用示例；说明已做/待做的一项最小动作。`journey.py status` 会区分助手准备完毕与用户完成体验。核心练习都验证后自动进入 daily；用户明确不想继续引导时可转 daily，但保留未完成状态。

日常模式直接响应“找文献、看不懂这段、PDF 扫描件、整理集合、引用出错”等具体问题。除非换电脑、环境损坏或用户要求，不再从下载软件讲起。
