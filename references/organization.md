# 导入和分类管理

先读取来源文件、目标库和现有集合，形成可检查的导入/调整清单；用户已明确要求在该范围导入或分类时，直接完成可逆的受支持操作，无需重复审批同一范围。

- 分类围绕论文问题/理论/方法/案例和阅读状态，优先复用已有集合；同一条目可以属于多个集合，不必复制 PDF。
- 去重先比较 DOI、规范化标题、作者和年份，列出候选。仅同题名不足以自动合并；合并、删除或覆盖需明确授权。
- 元数据核对 DOI、作者顺序、年份、期刊、卷期和页码。检索到的候选信息与已验证信息分开。DOI 导入不能保证完整正文可下载。
- 附件绑定到正确的父文献；保留原始资料路径与导入回执用于核对。没有授权不移动或重命名原文件。
- 优先 Zotero 原生导入/Connector 或当前版本官方支持的接口；不要直接写 SQLite。现有只读 MCP 不足以完成写入时，调查已支持的写入通道，准备具体方案，避免重复安装第二套 MCP。
- 批量写入采用可重入的小批次，逐批读回 ID、数量和父集合。失败重试前核对已创建的条目，防止重复导入。成功回执不代替实际库内读回。
- 云端 Web API 写入、云 OCR 上传需要相应授权；本机读取不应索取无关 Key。

标签/笔记回写同样遵守授权范围。把自动生成的研究卡片先交付为独立文件通常最容易审阅；若用户已要求写回指定条目则直接执行并读回验证。
