# PDF 和扫描件

先定位真实附件；缺失、未同步、加密、无文本层、乱码、提取被截断是不同问题。

`pdf_ops.py inspect INPUT --all-pages` 检查全页文本状态；默认只采样最多 12 页，输出 `partial_pages_unchecked` 时不能声称全文检查完成。启发式的 `no_text_layer` 也可能是空白或解析器不支持，先渲染疑难页确认。

需要 OCR 时：

1. 确认任务已授权在本地生成副本。执行 `pdf_ops.py ocr INPUT --output-bundle NEW_DIRECTORY --languages chi_sim+eng`（父目录须已存在），默认 `--mode skip` 保留已有文本页。
2. 乱码需要先确认原页面内容与字体映射问题；仅在明确决定重做文本层时选 `--mode redo`。强制栅格化 `--mode force` 会影响矢量、表单和交互内容，需要说明影响并取得范围明确的同意，不能用它当失败后的自动重试。
3. 只以 bundle 的 `report.json` 中 `status=complete` 作为流程成功；失败也可能留下诊断文件，不把中间 PDF 当成已交付。
4. 检查源文件 SHA256 没变、输出页数一致、全部页文字覆盖。抽查图文页面、中文、关键数字与双栏次序，才能评价识别质量。侧车文本可能跳过原有文本页，不等于整份 PDF 全文。
5. 保留原件；如需加入 Zotero，创建新附件并保留原 PDF 与批注关系，不把 OCR 文件覆盖到 storage 中。回写是独立动作，遵循已有授权。

脚本会拒绝已存在的输出、符号链接输出路径和 Zotero storage 输出；不会安装软件、下载模型或上传文件。使用已有 OCRmyPDF，缺依赖时报告实际缺项，按当前授权安装最小必要组件后再验证。

常见本地条件：Tesseract 的 `chi_sim` / `chi_tra` / `eng` 是识别语言；CJK 字体是另一个环节。OCR 返回 0 不代表中文可复制，检查输出文字及嵌入字体。遇到中文缺字先查当前 OCRmyPDF 渲染器与字体，不盲目重下全部语言包。

在线 OCR 是可选路线，先说明需上传哪些文件、用途、费用和保留政策，获得同意后才上传。无明确永久免费承诺的免费额度不能表述成永久免费。复杂表格/公式可评估 PaddleOCR、MinerU 等，但不预装整套依赖；先检查现有本地工具是否已够用。
